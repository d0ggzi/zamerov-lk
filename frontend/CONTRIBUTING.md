# Требования к frontend-коду (production)

Практический чек-лист для этого проекта (React 19 + Vite + React Router v7, без
TypeScript, стейт-менеджеров и data-fetching библиотек). Держим планку, чтобы код
оставался предсказуемым и поддерживаемым.

## 1. Слой API и данные

- **Все обращения к бэкенду — через `src/api/client.js` (`apiFetch`)**. Он единообразно
  ставит `Authorization`, сериализует JSON, проверяет статус и бросает `ApiError`.
  Не пишем «сырой» `fetch` в компонентах.
- Загрузка файлов в S3 — только через `src/api/s3.js` (`uploadFileToS3`). Не дублируем
  логику presigned-URL по месту.
- Каждый `fetch`/эффект с запросом должен уметь **отменяться** (`AbortController`),
  чтобы не обновлять состояние размонтированного компонента.

## 2. Обработка ошибок

- **Ошибку нельзя «глотать»**. Минимум — состояние ошибки в UI; `.catch(console.error)`
  без обратной связи пользователю в production недопустим.
- Есть глобальный `ErrorBoundary` (`src/components/error-boundary/`) — он ловит ошибки
  рендера. Он не отменяет локальную обработку ошибок запросов.
- Различаем типы ошибок: `ApiError` (ответ сервера, напр. 401 → разлогин) и сетевую/
  прочую ошибку (не рушим сессию).

## 3. React-паттерны

- Интерактивность (дропдауны, drawer, модалки) — **на React-состоянии**, а не на
  vanilla-JS `data-*` тогглах сторонних либ: их глобальный init гоняется в гонке с
  рендером SPA и срабатывает через раз.
- Навигация — через `<Link>`/`useNavigate` из React Router, а не `<a href>` с
  перезагрузкой страницы.
- Правильные зависимости эффектов; не создаём новые массивы/объекты-дефолты в пропсах
  на каждый рендер (выносим в модульные константы или мемоизируем).
- `key` в списках — стабильный id, не индекс массива.
- Побочные эффекты — в `useEffect`, а не в теле рендера.

## 4. Структура и переиспользование

- Структура папок: `api/`, `hooks/`, `context/`, `utils/`, `constants/`,
  `components/{layout,blocks,pages}`. Папка — kebab-case, файл компонента — PascalCase,
  default-export.
- Магические значения — в `constants/` (напр. роли в `constants/roles.js`).
- Общие Tailwind-строки — в `components/themes/default.js` или локальном `styles.js`.
  Дублирующуюся логику выносим в `utils/`/`hooks/`.

## 5. Качество и проверки перед PR

- `npm run lint` — без ошибок.
- `npm run test:run` — зелёный; на новую нетривиальную логику (utils, hooks) добавляем тест.
- `npm run build` — собирается.
- Никаких закоммиченных `console.log`, мёртвого кода и неиспользуемых зависимостей.

## 6. Безопасность и доступ

- Токен читаем/декодируем только через `context` + `useAuth`; ключ localStorage не
  хардкодим по месту.
- Доступ к роутам — через `ProtectedRoute` (+ `requiredRoles`). Защищённый контент не
  показываем до подтверждения авторизации.
- Внешние ссылки с `target="_blank"` — всегда `rel="noopener noreferrer"`.

## 7. Конфигурация

- Секреты и хосты — только через `import.meta.env.VITE_*` (см. `.env`), не хардкодим.
- Доступность: интерактивные элементы — `<button>`/`<a>` с понятной семантикой и
  `aria-label` там, где текст только иконочный.
